# The backend's coded-error contract: every `detail.code` string the server can send.
#
# Why this file exists. FlockErrorCode is hand-maintained, and the codes it mirrors ship with backend
# features rather than with SDK ones — so nothing connected the two, and the enum drifted silently. On
# 2026-08-31 a diff against the live spec found 25 documented codes with no member, seven of them on
# surface this SDK actually calls, including both Consume codes and the three reward codes that landed
# with the 1.36.0 shop work. Nobody noticed, because a missing member is not an error: it parses to
# Unknown and reads exactly like a failure the server chose not to code.
#
# The OpenAPI spec is not in this repo (it is the backend's artifact and lives beside it), and CI has no
# route to a running backend, so this file is the checked-in snapshot the consistency workflow diffs the
# enum against. Refreshing it is a deliberate act, and the point is that the refresh produces a reviewable
# one-line-per-code diff instead of silence.
#
# Format: one code per line. `#` starts a comment. A code under [waived] is one this SDK is not expected
# to have a member for; every other code must have one, or CI fails.
#
# This file is maintainer tooling: the `~` suffix keeps the folder out of Unity's AssetDatabase, and
# FlockPackageBuilder only walks Runtime/Editor/Samples/Documentation~, so it never ships in the package.
#
# To refresh, from a machine that can reach the backend:
#   curl -s http://localhost:8001/openapi.json > /tmp/live.json
#   grep -oE '"code"[[:space:]]*:[[:space:]]*"[a-z_]+\.[a-z_]+"' /tmp/live.json \
#     | grep -oE '[a-z_]+\.[a-z_]+' | sort -u
# then reconcile the result against the sections below. A code that appears and is not waived needs a
# FlockErrorCode member (name = the code PascalCased) and a hint in FlockErrorHints.cs.
#
# The spec is not the whole contract. On 2026-10-06 it no longer showed 18 codes listed under [documented]
# (most of shop.* and game_command.*), while the backend still defines and sends every one. Each backend
# package lists its codes in its enums.py, and the request-wide request.* codes are in
# common/helpers/error_codes.py, so read those as well when refreshing:
#   grep -rhoE '"[a-z_]+\.[a-z_]+"' <backend>/flock/packages/*/enums.py <backend>/common/helpers/error_codes.py \
#     | tr -d '"' | sort -u
#
# Last refreshed 2026-10-26, when the payment hardening merged into backend main (644bf45), for the shop, payment_provider and
# matchmaking codes, read in their code: shop.invalid_purchase_status and shop.idempotency_key_reused (waived, below) and
# matchmaking.search_input_required, which the ticket the SDK opens meets once a queue has region or skill rules. The codes of
# main's session backfill, live updates and session kicks (BACKLOG All-2, All-11) wait for the owner's scope call and are
# not listed. Before that, on 2026-10-23 for the payment hardening (backend fix/sdk-payment-hardening, not yet merged): four
# payment_provider codes and shop.player_mismatch and shop.player_required, read in its code. Before that, on
# 2026-10-22, for the shop and payment_provider codes (the payment routes), read in those two packages'
# code on the local backend (main aa402fc) and measured by the payment routes probe on 2026-10-21. Before that, on
# 2026-10-15, for the API key, sign-in and request.* codes, measured against the local backend.
# Before that, against the live backend: 2026-10-06 (93 codes in the spec, 105 /v1 paths), for the
# matchmaking, party and multiplayer codes and the codes the spec gained since 2026-08-31. On 2026-10-08
# the backend's matchmaking and session fixes added multiplayer.version_mismatch and
# matchmaking.version_mismatch and removed multiplayer.extras_paused (the relay now answers STUN only).

# Sent by the running server but absent from the spec, so a spec-only diff would never see them. Listed
# here so the member that handles each is not mistaken for dead code and removed.
#
# leaderboard.not_found  - the four /v1 leaderboard by-name routes declare only 200 and 422, yet an
#                          unknown board answers 404 with this code. Verified live 2026-08-31 against
#                          both /by-name/{name} and /by-name/{name}/standings.
# analytics.currency_not_found - observed live in July 2026 when a transaction named a currency the game
#                          had no entity for. Not in the current spec, and not reproduced since the
#                          backend took over code-to-id resolution on 2026-08-26; kept because absence
#                          from the spec is not evidence of absence from the server, as the line above
#                          demonstrates. Retire it only after checking the backend, not the spec.
# multiplayer.join_code_unavailable - 500 when creating a session finds no free join code after 8 tries.
# multiplayer.already_in_session - 409 when two requests seat one player at the same moment (a database
#                          race). Both read in the backend's multiplayer code on 2026-10-06, not seen live.
# shop.real_currency_needs_checkout - 422 from the purchase route for an item priced in a currency the game's
#                          currency config lists as real money; the route's documented responses leave it out.
#                          Read in the backend's shop settlement code on 2026-10-15.
# The backend also defines multiplayer.session_ended and multiplayer.invalid_connection_info, which nothing
# raises (2026-10-06), and matchmaking.queue_has_open_tickets, which only a dashboard route sends. None has
# a member; add one the day it can reach a game.
# game.missing_api_key, game.invalid_api_key - 401 from the API key check every /v1 route makes first (a blank
#                          key, an unknown one). A missing header never gets that far: the framework refuses it as
#                          request.validation_failed naming header.X-Flock-API-Key. Measured live 2026-10-15.
# player.missing_token, player.invalid_token - 401 from the sign-in check of a route that acts as the player (no
#                          bearer, a bearer that is not this game's). Measured live 2026-10-15; player.expired_token
#                          comes from the same check, read in the backend's code.
# request.* - the backend's own codes for a failure no route raised itself (common/helpers/error_codes.py): every
#                          /v1 error carries a code, falling back to one per status. request.not_found (a route
#                          that does not exist, as when API URL ends in /v1, or a record a route did not find), request.method_not_allowed and
#                          request.validation_failed (a member missing from the body) measured live 2026-10-15;
#                          the rest read in the backend's handler.
# payment_provider.* and shop.* below - from redeeming a store receipt (/v1/shop/validate-receipt) and opening a web
#                          checkout (/v1/shop/checkout), each measured live by the payment routes probe on 2026-10-21.
#                          The spec shows none of them: a route's own 422 codes are replaced there by the framework's
#                          "Validation failed" answer, and neither route declares its 503 (read in the spec 2026-10-22).
#                          receipt_invalid also answers 502 when the store cannot be reached, and
#                          real_currency_settlement_unavailable 503 when the server has no webhook address.
#                          shop.webhook_provider_unknown also comes from the webhook route the providers call.
#                          Their members come before any call of this SDK reaches these routes: the payment plan adds
#                          the codes first, then the store purchase call and web checkout, each in a release of its own.
